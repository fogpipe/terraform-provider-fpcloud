# client methods with no Terraform resource/data-source calling them, reviewed
# and accepted as permanent exclusions during the 2026-07-24 coverage sweep.
# Grouped and reasoned here for humans; scripts/tf-resource-coverage.ts only
# reads non-comment lines, so --update-baseline will flatten these groupings
# back to a plain list — re-annotate by hand after running it, or leave the
# groups as documentation and let a fresh entry land ungrouped at the bottom.

ProvisionUser

# read-only observability — not something you reference as TF resource state
GetAppLogs
GetAppVersion
# workload events (#126) — warnings the cluster emitted about pods that exist
# right now. They age out of the cluster on their own, so a data source over
# them returns a different set on every read and settles for nobody
ListWorkloadEvents
ListDeployments
GetDeployment
ListRevisions
ListAudit
ClusterInfo
FKECredentials
FKEToken
GetDatabaseConnection
# the project status document (#778) is the strongest case in this group: it is
# an observation of live cluster state that changes between two consecutive
# reads, so a data source over it would hand Terraform a value that never
# settles — a perpetual diff for anything referencing it, and a plan that
# depends on whether an app happened to be restarting
ProjectStatus

# "list all X" convenience — every existing data source in this provider is a
# singular lookup (project/app/database); a collection-listing data source has
# no precedent here and no clear use case yet
ListDatabases
ListBuckets
ListOrgSecrets

# scheduled-job runs (#166) — a run is a record of something that happened, not
# desired state: you can't declare "three runs should exist". `fpcloud_job`
# covers the schedule itself; triggering and reading runs stays CLI/API-only
RunJob
ListJobRuns
GetJobLogs

# "list all X" convenience (see above) — jobs are looked up singularly
ListJobs

# "list all X" convenience (see above) — runner pools are looked up singularly
ListRunners

# metered usage (#675) — read-only observability. Usage is produced by the
# platform, not declared: there is no desired state for "what this app consumed"
ListProjectUsage
ListOrgUsage

# organization writes (ADR-093, ADR-094) — an org is granted by an operator
# together with its first owner, so there is no fpcloud_org resource for these
# to hang on: a tenant able to declare an org in Terraform could raise its own
# ceiling by declaring a second. The ceiling and the FKE entitlement are the
# operator's to set for the same reason — a tenant that could write its own
# ceiling has no ceiling — and renaming is a one-line write on something
# Terraform does not own. fpcloud_org is a data source instead.
UpdateOrgDisplayName
UpdateOrgFKE
UpdateOrgQuota

# price books (ADR-090) — which book an org is billed against is assigned by
# the operator, not declared by the org: it grants nothing, so there is no
# entitlement for a plan to converge on, and a tenant able to write it would
# be choosing its own prices. The rates themselves are published by the
# platform, so reading them is reading someone else's desired state.
OrgPrices
OrgPriceBook
UpdateOrgPriceBook

# website versions (ADR-050) — a version is a record of what the site served,
# created by a deploy rather than declared. Terraform cannot make one exist,
# and the list moves every time anyone publishes.
ListWebsiteVersions

# billing reads (#109/#111) — same reasoning one level up: an estimate is a
# computation over usage that has not finished accruing, and an invoice is a
# record of a period that closed. Neither is desired state anyone declares.
# The billing ROLES are declarative and do have a resource (fpcloud_billing_binding)
GetBillingEstimate
ListInvoices
GetInvoice
# the price list is a published fact about the platform, identical for every
# caller — a data source would return the same rows to everyone and give
# Terraform a value nothing can be declared against
ListPrices

# github connection (#790, ADR-066) — cannot be declarative state: binding a
# project to a GitHub account requires a person to authorize the install in a
# browser as themselves, which is the entire proof. A Terraform resource could
# only ever assert an account name, which is what the ADR removed.
StartGitHubConnect
GetGitHubConnection
DisconnectGitHub
