# client methods with no Terraform resource/data-source calling them, reviewed
# and accepted as permanent exclusions during the 2026-07-24 coverage sweep.
# Grouped and reasoned here for humans, and maintained by hand:
# scripts/tf-resource-coverage.ts reads the non-comment lines and never writes
# this file (fogpipe/cloud-workspace#888), so add a new entry to the group it
# belongs to, with its reason.

# auth / identity — not infrastructure state
# A listing of accounts is a person's read (`fpcloud sa list`, the console);
# `fpcloud_service_account` reads itself by id through GetServiceAccount
# (ADR-284), so neither listing is a resource's.
ListOrgServiceAccounts
ListServiceAccounts
GetMe
# The role catalogue is the platform's, read by people (`fpcloud iam roles`,
# the console's grant drawer) to see what a role carries; a binding's `role`
# is a string the API validates against it on apply, so Terraform declares
# bindings and never the catalogue.
ListRoles
# --- one-shot operations and cross-project reads (fogpipe/cloud-workspace#306
#     bumped the client and surfaced these; each is a reviewed exclusion) -----
# The database tunnel's connection details (ADR-045, ADR-154): a credential
# minted per call and valid for that call. There is no state to converge on.
GetDatabaseConnection
GetReadOnlyDatabaseConnection
# A pool recycle (#145) is an operation with a lifetime, not a state. `apply`
# has no way to say "restart now and not again", so an attribute over it would
# either recycle on every apply or sit as permanent drift. `fpcloud runner
# restart` is the surface.
RestartRunner
# Waiting for that recycle to finish is the same operation, watched to its end.
WaitRunnerRestarted
# Deploying a catalog template (ADR-235) creates an app, a database and a
# bucket the practitioner did not declare, and `app upgrade` is an action on
# one of them, not a state. OpenTofu's surface is `data.fpcloud_template`,
# from which a module declares the three resources itself.
InstantiateTemplate
UpgradeApp
# Enumerating the catalog is a person's read — `fpcloud template list`, the
# console — and a data source names one entry.
ListTemplates
# `runner check` (#774) answers a question about text the caller supplies. It
# creates nothing, changes nothing and has no id — there is no resource for it
# to be.
CheckRunnerWorkflows
# Who did what inside a database tunnel (ADR-163), read from the log store for
# its retention. An observation of the past, and one that moves between two
# consecutive plans.
DatabaseAuditLog
AuthConfig
AuthSecurity

# imperative one-shot actions — not declarative resource state
CreateBackup
DeleteBackup
ListBackups
RestoreDatabase
RunBackupDestination
RestoreBackupDestination
RollbackApp
ReconcileApp
RestartApp
MoveProject
ApplyRetention
PreviewRetention
VerifyDomain
VerifyBucketDomain
PublishWebsiteVersion
ClearBucketLifecycleRules

# data-plane object operations — deliberately imperative, matches the
# aws_s3_bucket / aws s3 sync split already established for buckets (#389)
DeleteBucketObject
ListBucketObjects
PresignBucketObject
GetBucketCredentials
GetS3Credentials
ListRegistryRepositories
ListRegistryTags
DeleteRegistryTag
# the CVEs behind a tag (fogpipe/cloud-workspace#321): a scan result, read, never declared
ListRegistryCVEs
# the same answer for the image an app is RUNNING (fogpipe/cloud-workspace#934).
# A vulnerability list is a read of changing external facts — the same bytes
# gain CVEs as the scanner's database learns them — so it is not infrastructure
# state a plan can converge on, and a data source over it would diff on every
# refresh for reasons nobody declared.
ListAppCVEs
# asking for one image to be scanned now (fogpipe/cloud-workspace#940, ADR-214):
# a request that starts work and is followed to its verdict, not a state to hold.
ScanImage

# read-only observability — not something you reference as TF resource state
GetAppLogs
GetWebsiteLogs
GetAppVersion
# app events (#126) — warnings recorded against an app right now. They age out
# on their own, so a data source over them returns a different set on every
# read and settles for nobody
ListAppEvents
ListDeployments
ListAudit
# the project status document (#778) is the strongest case in this group: it is
# an observation of live cluster state that changes between two consecutive
# reads, so a data source over it would hand Terraform a value that never
# settles — a perpetual diff for anything referencing it, and a plan that
# depends on whether an app happened to be restarting
ProjectStatus
# the changelog (ADR-239) is what shipped in each release: a published fact a
# person reads — `fpcloud changelog`, the console — that grows with every
# release, so nothing a plan declares converges on it
Changelog

# "list all X" convenience — every existing data source in this provider is a
# singular lookup (project/app/database); a collection-listing data source has
# no precedent here and no clear use case yet
ListDatabases
# a database's subscriptions (ADR-172): each one IS declared, by
# fpcloud_database_subscription, which reads its own with GetDatabaseSubscription.
# Enumerating them is the same "list all X" shape as the line above, and the
# health it reports moves between two consecutive reads — a data source over it
# would hand Terraform a value that never settles.
ListDatabaseSubscriptions
ListBuckets

# scheduled-job runs (#166) — a run is a record of something that happened, not
# desired state: you can't declare "three runs should exist". `fpcloud_job`
# covers the schedule itself; triggering and reading runs stays CLI/API-only
RunJob
ListJobRuns
GetJobLogs

# "list all X" convenience (see above) — jobs are looked up singularly
ListJobs

# organization writes (ADR-093, ADR-094) — an org is granted by an operator
# together with its first owner, so there is no fpcloud_org resource for these
# to hang on: a tenant able to declare an org in Terraform could raise its own
# ceiling by declaring a second. The ceiling is the operator's to set for the
# same reason — a tenant that could write its own
# ceiling has no ceiling — and are no longer in pkg/client at all (ADR-089,
# fogpipe/cloud-workspace#121); renaming is a one-line write on something
# Terraform does not own. fpcloud_org is a data source instead.
UpdateOrgDisplayName

# price books (ADR-090) — which book an org is billed against is assigned by
# the operator, not declared by the org: it grants nothing, so there is no
# entitlement for a plan to converge on, and a tenant able to write it would
# be choosing its own prices; assigning it is fpadmin's and no longer in
# pkg/client (ADR-089). The rates themselves are published by the platform,
# so reading them is reading someone else's desired state.
OrgPrices

# website versions (ADR-050) — a version is a record of what the site served,
# created by a deploy rather than declared. Terraform cannot make one exist,
# and the list moves every time anyone publishes.
ListWebsiteVersions

# billing reads (#109/#111) — same reasoning one level up: an invoice is a
# record of a period that closed, not desired state anyone declares.
# The billing ROLES are declarative and do have a resource (fpcloud_billing_binding)
ListInvoices
GetInvoice
# what an org or a project cost (ADR-273, fogpipe/cloud-workspace#1144). Cost
# moves every hour, so a data source reading it would make every plan differ
# from the last with nothing changed; it is a read for people, not a value
# anything is declared against.
OrgCost
ProjectCost

# what an org or a project holds against its bound, per axis (ADR-279,
# fogpipe/cloud-workspace#1222). A read of live capacity, like cost: the
# provider gets no data source.
OrgCapacity
ProjectCapacity
# the price list is a published fact about the platform, identical for every
# caller — a data source would return the same rows to everyone and give
# Terraform a value nothing can be declared against
ListPrices

# github connection (#790, ADR-066) — cannot be declarative state: binding a
# project to a GitHub account requires a person to authorize the install in a
# browser as themselves, which is the entire proof. A Terraform resource could
# only ever assert an account name, which is what the ADR removed.
StartGitHubConnect
GetGitHubConnection
DisconnectGitHub

# Secrets (#1069, ADR-287): TF manages one secret per fpcloud_secret and reads
# it back by id; enumerating a project's or an organization's secrets is a
# CLI/console read (`fpcloud secret list [--org]`), not state anyone declares.
ListProjectSecrets
ListOrgSecrets

# A secret's value read (ADR-289): `fpcloud secret access`, `secret get
# --reveal` and the console's Reveal. fpcloud_secret.value is what the
# configuration wrote, already in state, so nothing in TF reads it back.
AccessSecret
